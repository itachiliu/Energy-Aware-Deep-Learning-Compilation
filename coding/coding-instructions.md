# 独立编码说明（交给第二编码者）

用途：为综述的 121 篇统计样本提供一份**独立**的第二轮编码，用于计算编码者间
一致性（Cohen's κ）。第二编码者请勿查阅附录 A 的总表、`coding-121-coderA.csv`
或正文中的类别计数，以免结果被锚定。

> **v2 更新**：第一轮独立编码暴露出规则模糊（机制 κ=0.29、边界 κ=0.26）。现已改
> 为按 **`coding-rubric-v2.md`** 判定，判据明确到"哪些情形不得记 Other""类别冲突
> 如何裁决""边界三者如何区分"。重编前请先通读该文件，再看 `calibration-sheet.csv`
> 中的分歧清单逐条校准。

## 两份表，任选一份

| 文件 | 规模 | 说明 |
|---|---|---|
| `coding-121-coderB-blank.csv` | 121 行 | 全量复核，最稳，约 3–4 小时 |
| `coding-audit-sample30-blank.csv` | 30 行 | 分层抽样（固定种子 20260909，覆盖十类），约 1 小时；期刊接受抽样验证 |

建议先做 30 行那份。若 κ 低于 0.6，回看分歧并修订判定规则后再抽一次，而不是直接
填完全量。

## 每行要填什么

给出的是文献编号、BibKey、标题、年份与发表载体。请据此（必要时查原文摘要）填写：

**1. category（类别，十选一）**

`建模` / `图层` / `循环层` / `稀疏` / `TinyML` / `异构` / `功耗` / `AI4C` / `测量` / `Pareto`

一篇文献只归入其论证功能最主要的一类。类别含义与判定细则见附录 A 表头的“受控词表”
说明以及 `supplements/code_matrix.py` 中的规则表。

**2. granularity（优化粒度，五选一）**

`Graph`（计算图层） / `Loop/Op`（循环与算子层） / `Placement`（异构放置） /
`Power`（功耗状态） / `Other`（不落在上述四类）

**3. mechanism（决策机制，五选一）**

`Analytical`（解析代价模型） / `Learned`（学习型代价模型） / `AutoSearch`（搜索式
自动调优） / `Agentic`（agentic / LLM 驱动的编译决策） / `Other`

注意：granularity 与 mechanism 是**两个独立维度**，都要填；若某篇文献不属于任何
四类粒度或四类机制，填 `Other`。

**4. boundary（边界，仅 121 行那份需要）**

`核心`（构成论证主线） / `桥接`（为方法学价值纳入的边界工作） / `前沿`（前沿观察性工作）

## 报送与计算

填好后把 CSV 放回 `supplements/` 目录，然后运行：

```bash
python repro/compute_audit30.py      # 30 行抽样
python repro/compute_kappa_two_coder.py   # 121 行全量
```

脚本输出各字段的样本量、一致率与 Cohen's κ，并写入 `repro/` 下的报告文件。

## 需要写进正文的信息

计算完成后请在报告里一并记录：复核者姓名（或匿名代号）、完成日期、是否读过本综述
正文，以及是否与两位作者存在共事关系。方法学小节需要如实说明这些条件。

## v2 双人独立编码轮（当前轮次）

前几轮的问题是"两人读同一份规则却编出两套结果"。本轮按标准做法分两步：先用
codebook 对齐口径，再各自独立编码，κ 只统计真正独立判断的部分。

**准备**

双方各自阅读，不交流：

1. `coding-rubric-v2.md`——判定顺序、`Other` 判据、类别裁决表、边界判据；
2. `codebook-v2-worked-examples.csv`——12 个已判例，每条给出字段、取值、规则条目与理由。

**编码**

| 编码者 | 表格 |
|---|---|
| A | `coding-sheet-A-v2.csv` |
| B | `coding-sheet-B-v2.csv` |

两张表内容完全相同（同一批 121 行，四个标签列全空）。填表规则：

1. `prefilled` 列标出的单元格已由 codebook 决定，**跳过不填**；
2. 其余单元格按规则独立填写，不得互相查看；
3. 同样**不得**查看附录 A、`coding-121-coderA.csv`、`coding-121-coderB-filled.csv`
   或 `code_matrix.py` 的输出——只要看过其中任何一个，这一轮的 κ 就失去意义；
4. 遇到规则未覆盖的情形，照常填写，并在 `prefilled` 列追加 `?` 标记，便于我们回头补规则。

**计算**

```bash
python repro/compute_kappa_v2.py
```

输出四个字段的 N、一致率与 Cohen's κ，并生成 `supplements/coding-121-final.csv`：
一致的单元格与 codebook 单元格已填好，分歧处留空，供两位编码者逐条决议。

**达标线**：四个字段的 κ 均不低于 0.6。未达标时，先看报告定位分歧集中在哪一类，
把规则补明确后再重编一轮，而不是直接改标签。

**需要在正文里如实说明的两点**：一是本轮使用 12 个 codebook 判例做先期校准，
对应的单元格不计入 κ（每个字段排除 3 个，实际统计 118 项）；二是编码者与作者
的关系、是否读过正文，都要记录下来。
