# 编码规则 v3（对象类型字段 + 机制归属补充）

本文件替代 v2 的第 4 节（`核心／桥接／前沿`），并在 v2 基础上补充两条机制归属
规则。v2 的其余部分（判定顺序、`Other` 判据、粒度定义、类别裁决表）继续有效。

## 一、用"对象类型"替换"边界"

v2 的 `核心／桥接／前沿` 把**对象类型**（通用编译栈／专用加速器／测量设施）与
**在本文中的重要性**混在一个字段里。重要性天然主观：两位编码者在 39 项上分歧，
κ 仅 0.463。v3 改为只编码对象类型，四值互斥、可机械判定。

| 取值 | 判据 | 典型例子 |
|---|---|---|
| `通用编译栈` | 对象是通用或生产级编译、运行时或 IR 栈 | TVM、TASO、DNNFusion、MLIR、ONNX Runtime |
| `专用加速器与体系结构` | 对象是专用加速器、数据流架构、ISA 或硬件设计空间 | Timeloop、Accelergy、Eyeriss、ReGate、CoSA |
| `测量与基准设施` | 对象是能耗测量方法、基准或报告规范 | MLPerf 系列、RAPL、Chaytan、ACT |
| `负载与模型层` | 对象是模型架构、压缩方法或端侧负载本身 | MCUNet、SparseGPT、NeurIPS 的量化工作 |

判定只看"这篇工作在研究什么对象"，不评它在本综述里有多重要。若一篇工作同时涉及
两类对象，按其**方法学贡献所依附的对象**判定：例如在通用编译器上实现、但服务于
专用加速器映射的工作，记 `专用加速器与体系结构`；给出通用测量方法但只在某类负载上
验证的，记 `测量与基准设施`。

与正文的关系：v2 里"桥接样本"的说法对应本字段中 `专用加速器与体系结构` 与
`测量与基准设施` 两类，正文相应表述一并更新。

## 二、机制归属补充规则

### M1：搜索框架优先于其内部模型

若论文的方法学贡献是**搜索、调度或自动调优框架本身**，记 `AutoSearch`，即使该框架
内部使用学习型或解析式代价模型。只有当**代价模型本身**构成论文的独立贡献时才记
`Analytical` 或 `Learned`。

| 例子 | 记 | 理由 |
|---|---|---|
| Ansor、MetaSchedule、AutoPhase、FlexTensor、Hidet | `AutoSearch` | 贡献是搜索框架，代价模型是内部组件 |
| nn-Meter、NeuralPower、NeurstrucEnergy | `Learned` | 贡献是可复用的学习型代价模型 |
| Timeloop、ZigZag、Mind Mappings | `AutoSearch` | 贡献是映射空间的搜索 |

### M2：`Other` 与 `Analytical` 的分界

纯表示、抽象或基础设施工作（编译器后端的表示层、稀疏张量代数、lowering 支持）既不
提出代价模型也不执行搜索，记 `Other`；但只要论文给出**解析式的开销、能耗或性能估计**
或成体系的规则化判定，就记 `Analytical`。

| 例子 | 记 | 理由 |
|---|---|---|
| TACO、Sparse Abstract Machine、MLIR 稀疏张量支持 | `Other` | 表示与基础设施，无模型无搜索 |
| Accelergy、逐层能耗估计、LLMCarbon、AccelWattch | `Analytical` | 给出解析式估计 |
